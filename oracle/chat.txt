BigQuery es el data warehouse (almacén de datos) en la nube de Google Cloud. Está diseñado para analizar grandes volúmenes de datos (desde gigabytes hasta petabytes) de forma rápida y sin necesidad de administrar servidores.
🔎 ¿Para qué sirve?
Analizar datos masivos con SQL
Crear dashboards y reportes (por ejemplo con Looker Studio)
Procesar datos en tiempo real
Hacer análisis predictivo y machine learning
Centralizar datos de múltiples fuentes
⚙️ Características principales
1️⃣ Serverless (sin servidores)
No necesitas configurar infraestructura. Google se encarga del escalado automático.
2️⃣ Muy rápido
Usa un motor de ejecución distribuido llamado Dremel, optimizado para consultas analíticas.
3️⃣ Usa SQL estándar
Permite consultas con Standard SQL, incluyendo:
JOIN
Subconsultas
Funciones analíticas
JSON
Ventanas (OVER)
Ejemplo simple:
SELECT country, COUNT(*) as total_users
FROM users
GROUP BY country
ORDER BY total_users DESC;
4️⃣ Integración con otras herramientas
Se conecta fácilmente con:
Google Analytics
Google Sheets
Cloud Storage
Dataflow
5️⃣ Machine Learning integrado
Con BigQuery ML puedes entrenar modelos directamente usando SQL:
CREATE MODEL modelo_ventas
OPTIONS(model_type='linear_reg') AS
SELECT ventas, publicidad
FROM dataset.tabla;
💰 ¿Cómo cobra?
BigQuery tiene dos modelos principales:
Por almacenamiento (cuánto guardas)
Por procesamiento (cuántos datos escanean tus consultas)
También existe modo de capacidad fija (reservas).
🚀 Ventajas
✅ No requiere administración
✅ Escala automáticamente
✅ Ideal para análisis masivo
✅ Alta disponibilidad
✅ Seguridad integrada
⚠️ Desventajas
❌ Puede ser costoso si no optimizas consultas
❌ No es base de datos transaccional (no es ideal para apps en tiempo real tipo CRUD)
🆚 ¿Con qué se compara?
Amazon Redshift
Snowflake
Azure Synapse Analytics
Si quieres, puedo explicártelo más técnico (arquitectura interna), más práctico (casos reales de uso) o compararlo con algo que ya conozcas 😊

1️⃣ ¿Qué es Dékuple y qué hacen?
Dékuple es un grupo francés de data marketing, líder en Europa y cotizado en la bolsa de París. Su foco está en:
🎯 Marketing basado en datos (data-driven marketing)
📊 Optimización de campañas
👥 Adquisición y retención de clientes
📈 Performance marketing y CRM
🤖 Activación de datos en múltiples canales (email, digital ads, etc.)
No son solo agencia creativa: son marketing + tecnología + datos.
Eso significa que el rol de Data Analyst no es solo hacer dashboards, sino:
Medir campañas
Analizar rentabilidad
Detectar oportunidades de optimización
Proponer mejoras que impacten en negocio
🔎 1. ¿Qué te van a preguntar en la entrevista?
Por la descripción del puesto, espera preguntas en 4 bloques:
🧠 A) SQL y bases de datos
Seguramente:
Diferencia entre INNER JOIN y LEFT JOIN
Cómo optimizar una query lenta
Agrupaciones (GROUP BY)
Subqueries
Casos prácticos tipo:
"Tenemos campañas, usuarios y conversiones. ¿Cómo calcularías el CPA?"
También pueden preguntarte:
Diferencias entre MySQL y PostgreSQL
Qué es una clave primaria / foránea
Índices
👉 Aquí estás bien preparado porque ya manejas MySQL.
📊 B) Visualización y BI
Te pueden preguntar:
Cómo decides qué gráfico usar
Qué KPI pondrías en un dashboard de campaña
Cómo presentarías resultados a alguien no técnico
Diferencia entre métrica y dimensión
Aquí Power BI y Excel avanzado te ayudan muchísimo.
📈 C) Marketing & negocio
MUY importante: este rol no es solo técnico.
Pueden preguntarte:

¿Qué métricas usarías para medir una campaña?
¿Cómo mejorarías la retención?
¿Qué es el ROI?
Diferencia entre CTR, CPC, CPA, LTV
Si una campaña baja en conversiones, ¿qué analizarías?
Prepárate esta parte bien.
🧩 D) Pensamiento analítico
Te pueden poner un caso:
"Una campaña tiene muchas impresiones pero pocas conversiones. ¿Qué harías?"
Buscan:
Enfoque estructurado
Hipótesis
Capacidad de priorización
Propuesta accionable
🚀 2. Cómo prepararte en 2 días (plan realista)
Te hago plan táctico:
📅 Día 1 – Técnico
✅ Repasar SQL avanzado
JOINs
GROUP BY + HAVING
Subqueries
CASE WHEN
Window functions (aunque sea por encima)
Haz 20 ejercicios en HackerRank o LeetCode SQL.
✅ Entender BigQuery (no necesitas dominarlo)
Solo necesitas saber:
Es un data warehouse en la nube de Google
Serverless
SQL estándar
Se paga por datos escaneados
Ideal para grandes volúmenes
No necesitas haberlo usado.
✅ Ver 2 tutoriales rápidos de Looker Studio
Es como Power BI pero más simple.
Conceptos clave:

Conectar fuente de datos
Crear gráficos
Dimensiones vs métricas
Filtros
Si sabes Power BI, lo entiendes rápido.
📅 Día 2 – Negocio y marketing
Aprende estos KPIs:
CTR = clicks / impresiones
CPC = coste / clicks
CPA = coste / conversiones
ROI = (ingresos - coste) / coste
LTV = valor total del cliente
Churn rate
Retención
Y prepárate para explicar cómo mejorar:
Segmentación
Funnel
A/B testing
Análisis por cohortes
🧱 3. Lo que no conoces (explicado fácil)
🔵 BigQuery (versión práctica)
Es básicamente:
“Una base de datos gigante en la nube optimizada para análisis masivo.”
Diferencias clave vs MySQL:
MySQL	BigQuery
Base transaccional	Base analítica
Manual	Serverless
Escala limitada	Escala enorme
Índices	Columnar
No necesitas instalar nada.
Solo haces SQL.
🟣 PostgreSQL
Es otra base relacional como MySQL.
Diferencias menores:
Más estricta con tipos
Mejor para funciones avanzadas
Muy usada en startups
Si sabes MySQL → sabes PostgreSQL al 80%.
🟡 Looker Studio
Es una herramienta de dashboards de Google.
Piensa:

Power BI → más potente
Looker Studio → más ligero y rápido

Conceptos:

Fuente de datos
Métricas
Dimensiones
Filtros
Parámetros
Si dominas Power BI, vas sobrado.

📌 Pensamiento estructurado
📌 Capacidad de traducir datos en decisiones
📌 Documentación
📌 Trabajo en equipo
📌 Mentalidad de negocio
